## 🎯 核心不变式实现

### 持久化不变式

> **M6-T6.4 核心不变式:**
> 
> 对于 DURABLE 执行，一旦接受逻辑操作并分配 operationId，
> 该逻辑操作必须在物理副作用能力调用被允许之前
> 成为持久化可达的。

**实现验证:**
```java
// executeDurableAllow() 中的顺序保证
String operationId = "OP-" + UUID.randomUUID();  // 1. 分配 operationId
PendingToolCall pending = new PendingToolCall(operationId, ...);  // 2. 构建
SuspensionCheckpoint checkpoint = new SuspensionCheckpoint(..., 
    ContinuationDisposition.RUNNABLE, pendingBatch, ...);  // 3. 包含
checkpointStore.create(checkpoint);  // 4. 持久化 (失败 = 抛异常)
// 5. Phase 6: 物理工具调用 (仅在 checkpoint 成功后)
```

✅ **顺序保证:** operationId → checkpoint → create() → delegate.call()

### 架构不变式

✅ **单一恢复脊柱:** CheckpointStore 唯一当前状态权威  
✅ **单一 CAS 模型:** checkpointVersion 唯一并发控制  
✅ **单一运行时绑定:** RuntimeBindingResolver  
✅ **单一重启检测:** executionEpoch  
✅ **单一物理尝试权威:** InvocationStateStore  
✅ **自描述 Checkpoint:** disposition 字段，无需上下文推断  
✅ **Schema 向后兼容:** 1.2 可读 1.0/1.1  
✅ **无第二恢复栈**  
✅ **无并行协调器**
