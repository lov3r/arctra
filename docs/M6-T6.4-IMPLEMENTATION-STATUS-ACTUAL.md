public record SuspensionCheckpoint(

```

```

## Phase 7: T5 物理调用集成 (100%)

### 核心实现

**文件**: `SpringAiToolCallingEngine.continueFromDurableCheckpoint()`

**关键流程**:

```java
1. 判断执行代次 (same vs cross incarnation)
   ├─ Same: 直接通过 ProtocolReconstructor 执行
   └─ Cross: 先进行恢复分类

2. 恢复分类 (InvocationRecoveryClassifier)
   ├─ 遍历 pendingBatch
   ├─ 调用 classifier.classify(processId, operation)
   └─ 检测 MayHaveInvoked → 抛出 RecoveryUncertaintyException

3. 执行工具 (ProtocolReconstructor)
   ├─ T5 invocation intent gate
   ├─ 生成唯一 attemptId  
   ├─ recordInvocationIntent(processId, operationId, attemptId)
   └─ delegate.call()

4. 模型续行
   ├─ 构建 continuation messages
   └─ chatClient.call()

5. CHECK B 删除
   ├─ deleteIfVersion(processId, version)
   └─ Phase 9 清理 invocationStateStore

6. 持久化最终assistant消息到ChatMemory
```

**T5 集成证据**:

- ✅ 使用 `ProtocolReconstructor.executeApprovedBatch()`
- ✅ 传递 `RecoveryClassificationResult` 列表
- ✅ 物理 `attemptId` 生成
- ✅ `InvocationStateStore.recordInvocationIntent()` 强制门控
- ✅ 混合物理/恢复执行路径

**与现有审批恢复的统一**:

```
DurableResumeCoordinator.resume()
  → SpringAiResumedExecutionHandler.executeResume()
    → ProtocolReconstructor.executeApprovedBatch()

SpringAiToolCallingEngine.continueFromDurableCheckpoint()
  → ProtocolReconstructor.executeApprovedBatch()
```

**同一个工具执行核心!**

### 已实现

**单语义状态**: RUNNABLE

```
generation N=1: RUNNABLE batch
  ↓
工具执行+模型续行
  ↓
CHECK B deleteIfVersion(N)
  ↓
完成
```

**executionEpoch 机制**:

```java
// 创建时标记当前代次
checkpoint = new SuspensionCheckpoint(
    ...
    ExecutionIncarnation.current()
);

// 恢复时比较代次
boolean isCrossIncarnation = 
    !checkpoint.executionEpoch().equals(ExecutionIncarnation.current());
```

### 未实现 (Phase 8 完整版)

**两步语义转换**:

```
N=1 RUNNABLE_BATCH
  ↓
工具执行完成
  ↓
CHECK B replaceIfVersion(N, N+1) 
  ↓

  ↓
模型调用
  ↓
CHECK B deleteIfVersion(N+1)
```

**当前简化理由**:

1. 工具结果当前在内存中 (ToolResponseMessage)

## Phase 9: 清理实现 (100%)

### InvocationStateStore 扩展

**新增方法**:

```java
/**
 * Delete all invocation state for a logical operation.
 * Best-effort cleanup after successful checkpoint deletion.
 */
void deleteInvocationState(String processId, String operationId);
```

**实现**:

1. **InMemoryInvocationStateStore**:
   ```java
   intents.keySet().removeIf(key ->
       key.processId().equals(processId) && 
       key.operationId().equals(operationId));
   resolutions.keySet().removeIf(key ->
       key.processId().equals(processId) && 
       key.operationId().equals(operationId));
   ```

2. **JdbcInvocationStateStore**:
   ```java
   DELETE FROM arctra_recovery_resolutions WHERE process_id = ? AND operation_id = ?
   DELETE FROM arctra_invocation_intents WHERE process_id = ? AND operation_id = ?
   ```

### 清理语义

```java
// CHECK B 成功后best-effort清理
try {
  for (PendingToolCall pending : pendingBatch) {
    invocationStateStore.deleteInvocationState(processId, pending.operationId());
  }
} catch (Exception e) {
  // 日志但不失败 - checkpoint 是权威
  System.err.println("Warning: InvocationStateStore cleanup failed: " + e);
}
```

**架构保证**:  
- ✅ Checkpoint 删除是关键事实  
- ✅ 清理失败不影响正确性  
- ✅ 过期状态不会干扰未来恢复
