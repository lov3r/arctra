# M6-T6.4 Phase 5 设计
## DURABLE ALLOW 逻辑操作物化

**目标:** 实现 ALLOW + DURABLE 执行路径，在工具批次物化后立即持久化

---

## 关键不变式

> 对于 DURABLE 执行：
> 
> 一旦接受逻辑操作并分配 operationId，
> 该逻辑操作必须在物理副作用能力调用被允许之前
> 成为持久化可达的。

**实现顺序:**

```
模型返回 tool calls
    ↓
治理评估 → ALLOW
    ↓
分配 operationId (每个工具)
    ↓
构建 PendingToolCall 列表
    ↓
检查持久性模式: context.durability()
    ↓
if DURABLE:
    创建/分配 processId
    ↓
    DURABLE COMMIT checkpoint (generation 1)
        - disposition: RUNNABLE
        - pendingBatch: [op-1, op-2, ...]
        - executionEpoch: current
    ↓
    checkpoint.create() 成功
    ↓
    自动继续 (内部，无需 resume API)
    ↓
    对每个操作:
        recordInvocationIntent()
        ↓
        delegate.call()
        ↓
        收集结果
    ↓
    构建继续输入
    ↓
    模型继续
    ↓
    CHECK B: deleteIfVersion() (完成)
```

## 实施策略

### 当前 execute() 流程

```java
@Override
public AgentResult execute(..., AgentExecutionContext context) {
    // 1. 创建 ToolCallingManager
    // 2. 创建 evidence 列表
    // 3. 包装工具 (evidence capturing)
    // 4. 创建 GovernanceToolCallingAdvisor
    
    try {
        // 5. 构建 ChatClient
        // 6. 执行模型调用
        // 7. 正常完成 → return AgentResult
        
    } catch (ToolApprovalRequiredSignal signal) {
        // 8. 治理悬挂
        return suspendForApproval(...);
    }
}
```

### 需要拦截点

当前 `GovernanceToolCallingAdvisor` 在工具调用前评估治理：
- ALLOW → 继续执行
- REQUIRE_APPROVAL → 抛出 ToolApprovalRequiredSignal

**问题:** ALLOW 路径立即执行工具，无持久化点。

### 解决方案选项

**选项 A: 在 GovernanceToolCallingAdvisor 内部拦截**

在 advisor 内部，ALLOW 决策后：
- 检查 context.durability()
- 如果 DURABLE，先物化 checkpoint
- 然后继续工具执行

**缺点:**
- Advisor 承担持久化职责（职责混乱）
- Advisor 需要访问 checkpointStore

**选项 B: 引入新的信号类型**

```java
class ToolExecutionReadySignal extends RuntimeException {
    PendingToolCall[] pendingBatch;
}
```

Advisor 抛出信号，Engine 捕获并处理持久化。

**缺点:**
- 使用异常控制流

**选项 C: 修改 advisor 返回模型**

Advisor 不直接执行工具，而是返回决策：
- ALLOW + 工具列表
- REQUIRE_APPROVAL + 悬挂状态

Engine 根据决策执行。

**缺点:**
- 需要重构现有 advisor 架构

**选项 D: 在 catch 后添加正常完成前拦截**

当前流程:
```
advisor → ALLOW → 工具执行 → 完成
```

修改为拦截工具执行结果，检查是否需要持久化。

**缺点:**
- 工具已经执行，晚了

---

## 推荐方案

**混合方案: 选项 B 变体**

引入 `DurableExecutionSignal` 作为**内部协调信号**：

```java
// Package-private, 仅用于 Engine 内部协调
class DurableExecutionRequiredSignal extends RuntimeException {
    GovernanceToolCallingAdvisor.SuspensionState state;
    boolean isApprovalRequired; // false for ALLOW, true for REQUIRE_APPROVAL
}
```

**实施步骤:**

1. **修改 GovernanceToolCallingAdvisor:**
   - ALLOW + DURABLE → 抛出 DurableExecutionRequiredSignal(state, false)
   - REQUIRE_APPROVAL → 抛出 DurableExecutionRequiredSignal(state, true)

2. **修改 SpringAiToolCallingEngine.execute():**
   ```java
   try {
       // 模型调用
   } catch (DurableExecutionRequiredSignal signal) {
       if (signal.isApprovalRequired) {
           return suspendForApproval(...);
       } else {
           return executeDurableAllow(...);
       }
   }
   ```

3. **实现 executeDurableAllow():**
   - 创建 processId
   - 构建 checkpoint (RUNNABLE)
   - checkpointStore.create()
   - 调用内部继续执行
