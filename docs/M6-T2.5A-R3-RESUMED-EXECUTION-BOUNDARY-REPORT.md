## C. Boundary Decision

### Conceptual Boundary Line

**Provider Execution Outcome ← | → Durable State Transition**

**Before boundary** (Spring AI mechanism):
- Protocol reconstruction (approved/rejected)
- Tool execution via ToolCallingManager
- Evidence collection
- Model continuation via ChatClient
- Governance evaluation
- ToolApprovalRequiredSignal detection

**After boundary** (Durable orchestration):
- CHECK B deleteIfVersion (completion)
- CHECK B replaceIfVersion (re-suspension)
- SUSPENDED / COMPLETED event emission
- ProcessFactory invocation
- Checkpoint version progression

### Exact Separation Point

The handler returns `ResumedExecutionOutcome`:
- `ModelCompleted(content, evidences)` - model finished, no approval needed
- `GovernanceSuspended(suspendedAssistant, evidences)` - new tools need approval

Orchestration layer receives outcome and performs CHECK B.

## D. Types Added

### 1. ResumedExecutionOutcome (sealed interface)

**Visibility**: package-private  
**Location**: `cn.bitcss.arctra.runtime.react.ResumedExecutionOutcome`  
**LOC**: 88

**Responsibility**: Represent Spring AI execution mechanism outcome without durable state transition semantics.

**Fields**:
- Common: `List<Evidence> evidences()`
- ModelCompleted: `String content`
- GovernanceSuspended: `AssistantMessage suspendedAssistant`

**Explicitly does NOT own**:
- Checkpoint version
- processId
- Durable COMPLETED truth
- Durable SUSPENDED truth
- AgentProcess creation

**Justification**: Clear semantic distinction between provider execution outcome and durable state transition. Prevents false implication that outcome = committed durable state.

**Visibility**: package-private  
**Location**: `cn.bitcss.arctra.runtime.react.SpringAiResumedExecutionHandler`

**Fields** (4):

**Methods**:

**Reason**: Would pass too many parameters (5: pendingBatch, binding, checkpointEvidences, signal, observationContext). Current direct parameter passing is acceptable for internal package-private API. Request type adds indirection without clear cohesion benefit for this specific boundary.

## G. Approved Resume Flow

### Before

```
SpringAiToolCallingEngine.resumeProcess()
  ├─ CHECK A (loadAndValidateCheckpoint)
  ├─ RuntimeBinding resolution
  ├─ APPROVAL_GRANTED event
  ├─ RESUMED event
  ├─ reconstructAndExecuteApproved() [Engine private method]
  │   └─ ProtocolReconstructor.executeApprovedBatch()
  ├─ durableContinueWithMessages()
  │   ├─ ChatClient.call()
  │   ├─ CHECK B deleteIfVersion (if completed)
  │   └─ CHECK B replaceIfVersion (if re-suspended)
  └─ AgentResult
```

### After (R3 Design)

```
SpringAiToolCallingEngine.resumeProcess()
  ├─ CHECK A (loadAndValidateCheckpoint)
  ├─ RuntimeBinding resolution
  ├─ APPROVAL_GRANTED event
  ├─ RESUMED event
  ├─ Delegate to SpringAiResumedExecutionHandler.executeResume()
  │   ├─ reconstructAndExecuteApproved() [Handler private]
  │   │   └─ ProtocolReconstructor.executeApprovedBatch()
  │   ├─ continueWithModel() [Handler private]
  │   │   └─ ChatClient.call()
  │   └─ Return ModelCompleted or GovernanceSuspended
  ├─ handleResumedExecutionOutcome()
  │   ├─ Case ModelCompleted:
  │   │   ├─ CHECK B deleteIfVersion
  │   │   ├─ COMPLETED event
  │   │   └─ persistCompletedAssistant()
  │   └─ Case GovernanceSuspended:
  │       ├─ APPROVAL_REQUIRED event
  │       ├─ CHECK B replaceIfVersion
  │       └─ SUSPENDED event
  └─ AgentResult
```

**Key Improvement**: Spring AI execution mechanism (protocol + tools + model) is now isolated from durable state transitions (CHECK B + events).

## I. Re-suspension Flow

### Semantic Split Achieved

**Handler responsibility**:
1. Detect `ToolApprovalRequiredSignal` during model continuation
2. Catch signal, extract suspended AssistantMessage
3. Return `GovernanceSuspended(suspendedAssistant, evidences)`

**Engine responsibility** (after receiving GovernanceSuspended):
1. Extract new PendingToolCall batch from suspendedAssistant
2. Emit APPROVAL_REQUIRED event
3. Build next checkpoint (version N+1)
4. CHECK B replaceIfVersion
5. Handle CHECKPOINT_CONFLICT if CAS fails
6. Emit SUSPENDED if CAS succeeds
7. Create AgentProcess via ProcessFactory

✅ **Handler does NOT**:
- Increment checkpoint version
- Call replaceIfVersion
- Emit SUSPENDED
- Create AgentProcess

## J. Completion Flow

### Semantic Split Achieved

**Handler responsibility**:
1. Model returns content without new tool calls
2. Return `ModelCompleted(content, evidences)`

**Engine responsibility** (after receiving ModelCompleted):
1. CHECK B deleteIfVersion
2. Handle CHECKPOINT_CONFLICT if CAS fails
3. Emit COMPLETED if CAS succeeds
4. Call `handler.persistCompletedAssistant()` **after** CHECK B succeeds

### ChatMemory Persistence Ordering

**Critical finding**: `persistCompletedAssistant()` is called **after** CHECK B deleteIfVersion succeeds.

**Crash window preserved** (M5 semantics):
```
CHECK B delete succeeds
→ COMPLETED event emitted
→ ChatMemory.add() called
→ [IF ChatMemory.add() FAILS: process is COMPLETED but final message not in memory]
```

**R3 does NOT change this ordering**. Handler owns the `persistCompletedAssistant()` method, but orchestration layer calls it at the correct time (after CHECK B).

**Justification**: Preserving existing semantics. ChatMemory failure recovery is out of R3 scope.

## K. Event Semantics

### Event Ordering Verification

**Approved Resume**:
1. APPROVAL_GRANTED (Engine)
2. RESUMED (Engine)
3. TOOL_EXECUTED (via Handler → ProtocolReconstructor → EvidenceCapturingToolCallback)
4. COMPLETED (Engine) OR APPROVAL_REQUIRED (Engine) + SUSPENDED (Engine)

**Rejected Resume**:
1. APPROVAL_REJECTED (Engine)
2. RESUMED (Engine)
3. (no TOOL_EXECUTED)
4. COMPLETED (Engine) OR APPROVAL_REQUIRED (Engine) + SUSPENDED (Engine)

**Re-suspension from Resumed**:
1. APPROVAL_REQUIRED (Engine, after receiving GovernanceSuspended outcome)
2. CHECKPOINT_CONFLICT (Engine, if CHECK B fails) OR SUSPENDED (Engine, if CHECK B succeeds)

**Unchanged**: ✅ All event types emitted at same points, same ordering, same payloads.

**Tool events**: Still emitted via ToolObservationContext passed to handler, which passes to ProtocolReconstructor, which passes to EvidenceCapturingToolCallback. Event emission architecture (R2) unchanged.
