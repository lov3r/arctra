## F. Spring Type Leakage Audit

### AssistantMessage in GovernanceSuspended

**Current**: `GovernanceSuspended(AssistantMessage suspendedAssistant, ...)`

**Analysis**:

**Option A (Current)**: Pass Spring AI AssistantMessage to Engine
- Engine extracts List<PendingToolCall> from AssistantMessage.getToolCalls()
- Leaks Spring AI protocol type back into durable orchestration

**Option B (Alternative)**: Handler converts to PendingToolCall
- Handler extracts List<PendingToolCall> before returning
- Durable orchestration only sees framework-neutral DTO

**Decision for R3.1**: ✅ **ACCEPTED CURRENT OWNERSHIP**

**Reason**:
- Conversion is trivial (.map(tc -> new PendingToolCall(...)))
- Moving conversion to Handler requires Handler to understand PendingToolCall DTO construction semantics
- Current leakage is minimal (one Spring AI type at internal boundary)
- Changing now adds churn without clear semantic benefit

**Recommendation**: **DEFERRED OWNERSHIP PRESSURE** - revisit if R4 coordinator extraction reveals cleaner boundary.

## H. Event Semantics

### Approved Resume Flow

1. ✅ APPROVAL_GRANTED (Engine, after CHECK A + signal validation)
2. ✅ RESUMED (Engine, before Handler delegation)
3. ✅ TOOL_EXECUTED (Handler → ProtocolReconstructor → EvidenceCapturingToolCallback)
4. ✅ COMPLETED (Engine, after CHECK B delete succeeds) OR
5. ✅ APPROVAL_REQUIRED (Engine, after receiving GovernanceSuspended)
6. ✅ SUSPENDED (Engine, after CHECK B replace succeeds)

### Rejected Resume Flow

1. ✅ APPROVAL_REJECTED (Engine, after CHECK A + signal validation)
2. ✅ RESUMED (Engine, before Handler delegation)
3. ✅ (zero TOOL_EXECUTED - rejected tools don't execute)
4. ✅ COMPLETED (Engine) OR APPROVAL_REQUIRED + SUSPENDED (Engine)

### Re-suspension from Resumed

1. ✅ APPROVAL_REQUIRED (Engine, after GovernanceSuspended outcome)
2. ✅ CHECKPOINT_CONFLICT (Engine, if CHECK B CAS fails) OR
3. ✅ SUSPENDED (Engine, if CHECK B CAS succeeds)

### Conflict Scenario

1. ✅ Both workers pass CHECK A
2. ✅ Both execute same tool (both emit TOOL_EXECUTED)
3. ✅ Winner CHECK B delete succeeds → COMPLETED
4. ✅ Loser CHECK B delete fails → CHECKPOINT_CONFLICT

**M5 Semantics**: ✅ **UNCHANGED** - Duplicate tool execution preserved (operation identity deferred to M6-T3)
