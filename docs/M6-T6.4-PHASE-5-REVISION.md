# M6-T6.4 Phase 5-9 实施计划修正

**关键发现:** 当前架构问题需要解决

---

## 问题分析

### 当前信号机制问题

**GovernanceToolCallingAdvisor 抛出 ToolApprovalRequiredSignal 用于:**
1. REQUIRE_APPROVAL → 需要外部批准
2. ALLOW + DURABLE → 需要持久化物化（M6-T6.4 新增）

**问题:** 使用同一个信号无法区分两种语义

**SpringAiToolCallingEngine 无法判断:**
- 这是真的需要批准吗？
- 还是只是需要持久化后自动继续？

---

## 解决方案

### 方案 A: 添加信号标识字段（推荐）

修改 `GovernanceToolCallingAdvisor.SuspensionState`:

```java
public record SuspensionState(
    ChatClientRequest originalRequest,
    AssistantMessage assistantMessageWithToolCalls,
    List<Evidence> evidences,
    boolean requiresApproval  // M6-T6.4: 区分 WAITING vs RUNNABLE
) {}
```

### 方案 B: 创建新信号类型

```java
class ToolDurableMaterializationSignal extends RuntimeException {
    SuspensionState state;
}
```

**缺点:** 两种信号，代码重复

### 方案 C: 在 SuspensionState 中包含 ContinuationDisposition

```java
public record SuspensionState(
    ChatClientRequest originalRequest,
    AssistantMessage assistantMessageWithToolCalls,
    List<Evidence> evidences,
    ContinuationDisposition disposition  // RUNNABLE or WAITING_FOR_SIGNAL
) {}
```

---

## 推荐实施

**采用方案 C:** 使用 `ContinuationDisposition`

**优点:**
- 明确语义（RUNNABLE / WAITING_FOR_SIGNAL）
- 与 checkpoint 模型一致
- 类型安全

**修改:**
1. 扩展 `SuspensionState` 添加 `disposition` 字段
2. `handleSuspendedBatch()` → WAITING_FOR_SIGNAL
3. `handleDurableBatch()` → RUNNABLE
4. `SpringAiToolCallingEngine` 根据 disposition 路由
