## 核心成果

### 持久化不变式实现

> **M6-T6.4 核心不变式:**
> 
> 对于 DURABLE 执行，一旦接受逻辑操作并分配 operationId，
> 该逻辑操作必须在物理副作用能力调用被允许之前
> 成为持久化可达的。

**实现验证:**
```
operationId 分配 
    ↓
checkpoint 构建 (RUNNABLE)
    ↓
checkpointStore.create() [失败 = 抛异常，无副作用]
    ↓
工具物理执行
    ↓
模型继续
    ↓
CHECK B deleteIfVersion()
    ↓
完成
```

### 架构不变式验证

✅ **单一恢复脊柱:** CheckpointStore 唯一当前状态权威  
✅ **单一 CAS 模型:** checkpointVersion 唯一并发控制  
✅ **单一运行时绑定:** RuntimeBindingResolver  
✅ **单一重启检测:** executionEpoch  
✅ **单一物理尝试权威:** InvocationStateStore  
✅ **自描述 Checkpoint:** disposition 字段，无需上下文推断  
✅ **Schema 向后兼容:** v1.2 可读 v1.0/v1.1  
✅ **无第二恢复栈**  
✅ **无并行协调器**

## 关键设计决策

### 决策 #1: 自描述继续状态
**决策:** 添加 `ContinuationDisposition` 到 `SuspensionCheckpoint`  
**理由:** 拒绝从使用上下文推断，checkpoint 自描述  
**影响:** Schema v1.2，向后兼容

### 决策 #2: 持久性选择权威
**决策:** `AgentExecutionContext.durability()` 执行级别选择  
**理由:** 单一权威源，避免配置冲突  
**影响:** Public API 扩展，默认 EPHEMERAL

### 决策 #3: 信号机制收敛
**决策:** 扩展 `SuspensionState` 添加 disposition，统一使用 `ToolApprovalRequiredSignal`  
**理由:** 避免信号类型膨胀，通过 disposition 路由  
**影响:** GovernanceToolCallingAdvisor 和 SpringAiToolCallingEngine 修改

### 决策 #4: 内部自动继续
**决策:** RUNNABLE checkpoint 后立即内部继续  
**理由:** 避免外部 resume API 开销，提高性能  
**影响:** Phase 6 实施，continueFromDurableCheckpoint() 方法
