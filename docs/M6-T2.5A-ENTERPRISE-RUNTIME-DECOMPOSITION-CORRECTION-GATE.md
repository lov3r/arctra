# M6-T2.5A — 企业运行时分解设计修正门

**审查日期**: 2024 M6-T2.5A  
**审查性质**: 基于企业平台目标的架构重新评估  
**前置审查**: M6-T2.5 运行时分解与可测试性架构门（已接受源真相发现）

## A. 修正后的执行决策

### 决策：**GO — 架构整合必需，M6-T3 前置条件**

**关键变更**：
- ❌ **拒绝** M6-T2.5 的"V1 后可选重构"建议
- ✅ **要求** M6-T3 之前完成架构整合
- ✅ **确认** 持久编排提取不可延期

### 理由

M6-T2.5 原建议基于假设：
> "保持当前结构的条件：不添加更多持久路径职责"

但企业平台路线图**明确将添加**：
- 持久运行时语义
- 操作身份（operationId）
- 工具尝试跟踪
- 重试机制
- 幂等性保障
- 恢复规划
- 工作者执行
- 远程执行
- 多执行提供者
- 可观测性深度集成
- 多租户平台服务

**结论**：当前结构的"可接受"条件已失效。

## B. 企业平台目标如何改变门审查

### 战略目标

Arctra 必须演进为完整的企业级 Agent 平台，而非仅是小型 V1 执行库。

### 架构要求

**持久运行时语义** 必须能够：
- 独立于 Spring AI 执行机制演进
- 支持多个执行提供者（未来）
- 支持持久操作追踪（未来）
- 支持远程/分布式执行（未来）
- 支持平台级可观测性（未来）

### 当前风险

**原 M6-T2.5 建议的 DurableResumeCoordinator**：

```java
final class DurableResumeCoordinator {
    CheckpointStore checkpointStore;
    RuntimeBindingResolver bindingResolver;
    String runtimeBindingKey;
    ProtocolReconstructor protocolReconstructor;
    ExecutionEventListener eventListener;
    List<ToolCallback> tools;              // ← Spring AI
    ChatModel chatModel;                   // ← Spring AI
    ChatMemory chatMemory;                 // ← Spring AI
    ToolGovernancePolicy governancePolicy; // ← Spring AI
}
```

**问题诊断**：
- 🔴 包含所有 Spring AI 执行依赖
- 🔴 风险：将上帝对象从 Engine 搬迁到 Coordinator
- 🔴 持久编排与 Spring AI 执行机制仍完全耦合
- 🔴 未来添加另一个执行提供者需要修改协调器核心

**这不是有效的职责分解，而是代码搬迁。**

## C. 当前混合职责分析

### 两种不同的职责必须明确区分

#### 职责 A：持久编排（Arctra 运行时行为）

**拥有语义**：
- CHECK A（checkpoint 栅栏）
- RuntimeBinding 解析
- 批准/拒绝决策接受
- 恢复生命周期
- CHECK B（checkpoint 转换）
- 重新暂停转换
- 持久生命周期事件（RESUMED, SUSPENDED, COMPLETED, CHECKPOINT_CONFLICT）

**特征**：
- 与执行提供者无关
- 是 Arctra 核心运行时语义
- 未来可支持多种执行后端

#### 职责 B：Spring AI 恢复执行机制（提供者集成行为）

**拥有机制**：
- ChatClient 构建
- ChatModel 调用
- Spring AI Prompt/Message 协议
- ToolCallingManager
- ToolCallback 注册
- GovernanceToolCallingAdvisor
- 协议重建（PendingToolCall → Spring AI Message）
- 模型继续
- Spring AI 对话协议

**特征**：
- 特定于 Spring AI 集成
- 提供者实现细节
- 未来可有其他提供者实现

### 当前问题

**SpringAiToolCallingEngine 中这两种职责完全交织**：

| 方法 | 持久编排 | Spring AI 执行 |
|------|---------|---------------|
| `resumeProcess()` | CHECK A, binding, 事件 | 无 |
| `loadAndValidateCheckpoint()` | ✓ | 无 |
| `resolveBinding()` | ✓ | 无 |
| `reconstructAndExecuteApproved()` | 协调 | ProtocolReconstructor 调用 |
| `durableContinueWithMessages()` | CHECK B, 事件 | ChatClient, Advisor 构建 |
| `handleDurableReSuspension()` | CHECK B, 版本递增 | 无 |
| `ProtocolReconstructor.executeApprovedBatch()` | 无 | ✓ 协议 + 执行 |

**没有清晰边界分离这两种职责。**

- **职责**：逻辑绑定标识
- **归属**：持久语义（核心）
- **理由**：配置标识，提供者无关

#### ExecutionEventListener ✅ 正确归属
- **职责**：事件观察
- **归属**：观察（核心）

#### ChatMemory ⚠️ Spring AI 机制
- **职责**：对话历史
- **归属**：Spring AI 执行

#### List<ToolCallback> ⚠️ Spring AI 机制
- **职责**：工具注册表
- **归属**：Spring AI 执行
- **理由**：Spring AI 特定接口
- **持久编排应依赖此吗？** ❌ 否

#### ToolGovernancePolicy ⚠️ Spring AI 机制
- **职责**：治理决策
- **归属**：治理（可能是核心，但当前通过 Spring AI Advisor 实现）
- **理由**：当前实现耦合 Spring AI
- **持久编排应依赖此吗？** ⚠️ 治理语义是核心，但实现细节是提供者相关

#### ProtocolReconstructor ⚠️ Spring AI 机制
- **职责**：协议重建 + 工具执行
- **归属**：Spring AI 执行
- **理由**：PendingToolCall → Spring AI Message，完全 Spring AI 特定

### 结论

**持久编排协调器应该只依赖**：
- ✅ CheckpointStore（状态权威）
- ✅ RuntimeBindingResolver（绑定解析）
- ✅ runtimeBindingKey（配置）
- ✅ ExecutionEventListener（观察）
- ✅ **恢复执行协作者**（而非直接依赖 Spring AI 组件）

**持久编排协调器不应该直接依赖**：
- ❌ ChatModel
- ❌ ChatMemory
- ❌ List<ToolCallback>
- ❌ ToolGovernancePolicy（实现细节）
- ❌ ProtocolReconstructor（Spring AI 特定）

|------|-----------|------------------------|-------------------|---------------------|
| CheckpointStore | CHECK A/B | 运行时语义 | 否 | 否 |
| RuntimeBindingResolver | 绑定解析 | 运行时语义 | 否 | 否 |
| runtimeBindingKey | 配置标识 | 运行时语义 | 否 | 否 |

**结论**：5/9 依赖应该属于 Spring AI 恢复执行协作者，而非持久编排协调器。

### 修正后的 DurableResumeCoordinator

**应该是**：
```java
final class DurableResumeCoordinator {
    // 持久语义依赖
    private final CheckpointStore checkpointStore;
    private final RuntimeBindingResolver bindingResolver;
    private final String runtimeBindingKey;
    private final ExecutionEventListener eventListener;
    
    // 恢复执行协作者（多态边界）
    private final ResumedExecutionHandler resumedExecutionHandler;
    
    AgentResult resume(
        String processId,
        long checkpointVersion,
        ContinuationSignal signal) {
        
        // CHECK A
        SuspensionCheckpoint checkpoint = loadAndValidateCheckpoint(...);
        
        // 解析 RuntimeBinding
        RuntimeBinding binding = resolveBinding(checkpoint);
        
        // 发射批准事件
        emitApprovalEvent(signal, checkpoint);
        
        // 发射 RESUMED 事件
        emitResumedEvent(checkpoint);
        
        // 委托给恢复执行处理器
        ResumeExecutionRequest request = new ResumeExecutionRequest(
            checkpoint,
            binding,
            signal
        );
        
        ResumeExecutionResult result = resumedExecutionHandler.executeResume(request);
        
        // CHECK B 处理
        if (result.completed()) {
            handleCompletion(checkpoint);
        } else if (result.resuspended()) {
            handleReSuspension(checkpoint, result.newPendingBatch(), result.evidences());
        }
        
        return result.agentResult();
    }
}
```

**关键改进**：
1. ✅ 协调器只依赖持久语义组件
2. ✅ Spring AI 执行细节委托给 `ResumedExecutionHandler`
3. ✅ 未来可以有其他提供者实现 `ResumedExecutionHandler`
4. ✅ 协调器不知道 ChatModel、ChatMemory、ToolCallback

## F. Spring AI 恢复执行边界

### 新边界：ResumedExecutionHandler

**职责**：
- 接受持久恢复请求（checkpoint + binding + signal）
- 执行提供者特定的恢复机制
- 返回执行结果（完成 / 重新暂停）

**接口**（概念草图，名称未冻结）：
```java
/**
 * 恢复执行处理器。
 * 
 * 提供者特定的恢复执行实现。
 * 持久编排协调器通过此接口委托实际执行，而不直接依赖提供者机制。
 */
interface ResumedExecutionHandler {
    
    /**
     * 执行恢复。
     * 
     * @param request 恢复执行请求（checkpoint, binding, signal）
     * @return 执行结果（完成/重新暂停）
     */
    ResumeExecutionResult executeResume(ResumeExecutionRequest request);
}

record ResumeExecutionRequest(
    SuspensionCheckpoint checkpoint,
    RuntimeBinding binding,
    ContinuationSignal signal
) {}

sealed interface ResumeExecutionResult {
    AgentResult agentResult();
    List<Evidence> evidences();
    
    record Completed(AgentResult agentResult, List<Evidence> evidences) 
        implements ResumeExecutionResult {
        boolean completed() { return true; }
        boolean resuspended() { return false; }
    }
    
    record Resuspended(
        AgentResult agentResult,
        List<Evidence> evidences,
        List<PendingToolCall> newPendingBatch
    ) implements ResumeExecutionResult {
        boolean completed() { return false; }
        boolean resuspended() { return true; }
    }
}
```

### Spring AI 实现

**SpringAiResumedExecutionHandler** (package-private):
```java
final class SpringAiResumedExecutionHandler implements ResumedExecutionHandler {
    private final ChatModel chatModel;
    private final ChatMemory chatMemory;
    private final List<ToolCallback> tools;
    private final ToolGovernancePolicy governancePolicy;
    private final ExecutionEventListener eventListener;
    
    @Override
    public ResumeExecutionResult executeResume(ResumeExecutionRequest request) {
        // 获取对话历史
        List<Message> conversationHistory = 
            chatMemory.get(request.binding().context().sessionId());
        
        // 协议重建（批准 / 拒绝）
        List<Message> continuationMessages;
        List<Evidence> newEvidences = new ArrayList<>();
        
        if (request.signal() instanceof ApprovalSignal approval) {
            if (approval.approved()) {
                continuationMessages = reconstructAndExecuteApproved(
                    request.checkpoint(),
                    conversationHistory,
                    newEvidences);
            } else {
                continuationMessages = reconstructDenialResponses(
                    request.checkpoint(),
                    conversationHistory);
            }
        }
        
        // 模型继续
        String content = continueWithSpringAi(
            continuationMessages,
            request.binding().definition(),
            newEvidences);
        
        // 合并 evidences
        List<Evidence> mergedEvidences = new ArrayList<>(
            request.checkpoint().accumulatedEvidences());
        mergedEvidences.addAll(newEvidences);
        
        // 返回完成结果（简化示例，实际需处理重新暂停）
        return new ResumeExecutionResult.Completed(
            new AgentResult(content, mergedEvidences),
            mergedEvidences);
    }
}
```

### 边界评估

**职责清晰性**：✅
- DurableResumeCoordinator：持久编排
- SpringAiResumedExecutionHandler：Spring AI 执行

**依赖方向**：✅
```
DurableResumeCoordinator
        ↓ (依赖接口)
ResumedExecutionHandler (接口)
        ↑ (实现)
SpringAiResumedExecutionHandler
```

**未来扩展性**：✅
- 添加新执行提供者：实现 `ResumedExecutionHandler`
- 协调器无需修改

**是否过度抽象**：⚠️ 需验证
- 当前只有 Spring AI 一个实现
- 但企业路线图明确多提供者需求
- 抽象基于真实职责分离，而非猜测

**建议**：✅ **接受此边界**
- 保持 package-private（非公共 SPI）
- V1 只有 Spring AI 实现
- 为未来多提供者奠定架构基础

## G. ProtocolReconstructor 重新评估

### 当前职责

**M6-T2.5 发现**：
- `constructDenialResponses()`：纯协议重建 ✅
- `executeApprovedBatch()`：协议重建 + 工具执行 + Evidence + 事件 ⚠️

### 归属判断

**问题**：ProtocolReconstructor 应该属于哪里？

**答案**：**Spring AI 恢复执行实现细节**

**理由**：
1. PendingToolCall → Spring AI AssistantMessage.ToolCall（Spring AI 特定）
2. 构建 Spring AI ChatResponse（Spring AI 特定）
3. 使用 Spring AI ToolCallingManager（Spring AI 特定）
4. 返回 Spring AI Message 列表（Spring AI 特定）

**结论**：ProtocolReconstructor 是 Spring AI 集成逻辑，不是核心持久语义。

### SuspensionCheckpoint 依赖问题

**当前**：
```java
// ProtocolReconstructor.executeApprovedBatch() 接受：
String processId,
Long checkpointVersion,
ExecutionEventListener eventListener
```

**M6-T2.5 建议简化为**：
```java
SuspensionCheckpoint checkpoint  // 从中获取 processId/version
```

**问题诊断**：
- SuspensionCheckpoint 是 Arctra 持久领域状态
- ProtocolReconstructor 是 Spring AI 集成逻辑
- **不应该让 Spring AI 集成代码直接依赖 Checkpoint 权威**

**修正建议**：
```java
// 在持久编排层转换：
String processId = checkpoint.processId();
Long version = checkpoint.checkpointVersion();

// 传递给 Spring AI 层：
protocolReconstructor.executeApprovedBatch(
    checkpoint.pendingBatch(),  // DTO
    conversationHistory,
    historicalEvidences,
    newEvidences,
    processId,          // 原始值
    version,            // 原始值
    eventListener);
```

**理由**：
- Checkpoint 停留在持久编排边界
- Spring AI 层只接收必要的原始值
- 避免提供者集成代码依赖核心领域权威

### 重命名评估

**当前名称**：`ProtocolReconstructor`  
**准确性**：部分误导（执行 > 重建）  
**建议**：保持当前名称，理由：
- `executeApprovedBatch()` 方法名已准确
- 类名虽不完美但未严重误导
- 重命名成本 > 收益（V1 后可重新评估）

record ToolObservationContext(

            throw new IllegalArgumentException("checkpointVersion must be positive");
        }
    }
}

## M. 初始执行调用流

### 正常完成路径

```
用户
  → AgentRuntime.execute()
      → SpringAiToolCallingEngine.execute()
          → 工具包装 (EvidenceCapturingToolCallback, 无事件上下文)
          → ChatClient.prompt()
              → MessageChatMemoryAdvisor.before() (加载历史)
              → GovernanceToolCallingAdvisor.adviseCall()
                  → [工具调用循环]
                  → 治理评估
                      → ALLOW: ToolCallingManager 执行
                      → DENY: 构建拒绝响应，继续
                      → REQUIRE_APPROVAL: ↓ 暂停
              → MessageChatMemoryAdvisor.after() (持久化)
          → 返回 AgentResult(content, evidences)
```

### 临时暂停路径

```
治理决策 REQUIRE_APPROVAL
  → 抛出 ToolApprovalRequiredSignal
      → SpringAiToolCallingEngine.execute() catch
          → suspendForApproval()
              → isDurableMode() ? 
                  NO → suspendForApprovalEphemeral()
                          → ProcessFactory.createSuspended(continuationFunction)
                          → 返回 AgentResult(partial, evidences, process)
```

### 持久暂停路径

```
治理决策 REQUIRE_APPROVAL
  → 抛出 ToolApprovalRequiredSignal
      → SpringAiToolCallingEngine.execute() catch
          → suspendForApproval()
              → isDurableMode() ? 
                  YES → suspendForApprovalDurable()
                          → 生成 processId
                          → 构建 PendingToolCall batch
                          → emitEvent(APPROVAL_REQUIRED)
                          → checkpointStore.create(checkpoint v1)
                          → emitEvent(SUSPENDED)
                          → ProcessFactory.createDurableSuspended(processId, 1L, this)
                          → 返回 AgentResult(partial, evidences, process)
```

**所有权**：
- 工具包装：SpringAiToolCallingEngine
- 治理决策：GovernanceToolCallingAdvisor
- 暂停决策：SpringAiToolCallingEngine
- Checkpoint 创建：CheckpointStore（通过 Engine）
- 事件发射：ExecutionEventListener（通过 Engine）

## N. 批准的持久恢复调用流

### 调用入口

```
用户批准
  → AgentProcess.resume(ApprovalSignal.approved())
      → DurableResumeStrategy.resume()
          → SpringAiToolCallingEngine.resumeProcess(processId, version, signal)
```

### 持久编排流（DurableResumeCoordinator）

```
DurableResumeCoordinator.resume(processId, version, signal)
  │
  ├─ CHECK A: loadAndValidateCheckpoint(processId, version)
  │   └─ checkpointStore.load() + 版本验证
  │       → StaleCheckpointException (if version mismatch)
  │       → CheckpointNotFoundException (if not found)
  │
  ├─ 解析 RuntimeBinding
  │   └─ bindingResolver.resolve(processId, bindingKey, sessionId)
  │       → ResumePreparationException (if resolution fails)
  │
  ├─ 发射批准事件
  │   └─ emitEvent(APPROVAL_GRANTED, checkpoint.version)
  │
  ├─ 发射 RESUMED 事件
  │   └─ emitEvent(RESUMED, checkpoint.version)
  │
  ├─ 委托恢复执行
  │   └─ ResumeExecutionRequest(checkpoint, binding, signal)
  │       → resumedExecutionHandler.executeResume(request)
  │           ↓
  └─ 接收执行结果并处理 CHECK B
```

### Spring AI 恢复执行流（SpringAiResumedExecutionHandler）

```
SpringAiResumedExecutionHandler.executeResume(request)
  │
  ├─ 获取对话历史
  │   └─ chatMemory.get(sessionId)
  │
  ├─ 协议重建 + 工具执行
  │   └─ if APPROVED:
  │       → ProtocolReconstructor.executeApprovedBatch(
  │           checkpoint.pendingBatch(),
  │           conversationHistory,
  │           historicalEvidences,
  │           newEvidences,
  │           ToolObservationContext(processId, version, listener))
  │               │
  │               ├─ 重建 AssistantMessage (ToolCalls from PendingToolCall)
  │               ├─ 重建 ChatResponse
  │               ├─ 工具包装 (EvidenceCapturingToolCallback + ToolObservationContext)
  │               │   └─ 执行时发射 TOOL_EXECUTED / TOOL_FAILED
  │               ├─ ToolCallingManager.executeToolCalls()
  │               └─ 返回 continuation messages (with ToolResponseMessages)
  │
  ├─ 模型继续
  │   └─ continueWithSpringAi(continuationMessages, definition, newEvidences)
  │       → ChatClient.prompt()
  │           → GovernanceToolCallingAdvisor (可能再次暂停)
  │           → ChatModel 调用
  │           → 返回 content
  │               OR 抛出 ToolApprovalRequiredSignal (重新暂停)
  │
  └─ 构建结果
      → if 完成: ResumeExecutionResult.Completed(agentResult, evidences)
      → if 重新暂停: ResumeExecutionResult.Resuspended(agentResult, evidences, newBatch)
```

### CHECK B 处理（DurableResumeCoordinator）

```
收到 ResumeExecutionResult
  │
  ├─ if result.completed():
  │   → handleCompletion(checkpoint)
  │       ├─ checkpointStore.deleteIfVersion(processId, version)
  │       │   → false: emitEvent(CHECKPOINT_CONFLICT)
  │       │            throw CheckpointTransitionConflictException
  │       │   → true:  emitEvent(COMPLETED)
  │       │
  │       └─ persistCompletedAssistant(context, content)
  │
  └─ if result.resuspended():
      → handleReSuspension(checkpoint, newBatch, evidences)
          ├─ 构建新 checkpoint (vN+1)
          ├─ emitEvent(APPROVAL_REQUIRED)
          ├─ checkpointStore.replaceIfVersion(processId, oldVersion, newCheckpoint)
          │   → false: emitEvent(CHECKPOINT_CONFLICT)
          │            throw CheckpointTransitionConflictException
          │   → true:  emitEvent(SUSPENDED)
          │
          └─ ProcessFactory.createDurableSuspended(processId, vN+1, coordinator)
```

**所有权**：
- CHECK A/B：DurableResumeCoordinator
- 批准事件：DurableResumeCoordinator
- 协议重建：SpringAiResumedExecutionHandler → ProtocolReconstructor
- 工具执行：ProtocolReconstructor → ToolCallingManager
- 工具事件：EvidenceCapturingToolCallback
- 模型继续：SpringAiResumedExecutionHandler
- Checkpoint 转换：CheckpointStore（通过 Coordinator）

## P. 并发恢复调用流

### 场景：两个并发 resume 调用

```
Thread A: resume(processId, version=1, APPROVED)
Thread B: resume(processId, version=1, APPROVED)
```

### 执行序列

```
时刻 T1: Thread A - CHECK A 通过 ✓
时刻 T2: Thread B - CHECK A 通过 ✓ (两者都通过)

时刻 T3: Thread A - 执行工具批次 (Weather API 调用)
时刻 T4: Thread B - 执行工具批次 (Weather API 调用) - 重复！

时刻 T5: Thread A - 模型继续，生成答案
时刻 T6: Thread B - 模型继续，生成答案

时刻 T7: Thread A - CHECK B deleteIfVersion(processId, 1)
                    → CAS 返回 true ✓
                    → emitEvent(COMPLETED)
                    → 返回 AgentResult

时刻 T8: Thread B - CHECK B deleteIfVersion(processId, 1)
                    → CAS 返回 false ✗ (checkpoint 已被删除)
                    → emitEvent(CHECKPOINT_CONFLICT)
                    → throw CheckpointTransitionConflictException ✗
```

### 语义保证

**At-Least-Once 工具执行**：
- ✅ CHECK A 允许并发通过
- ⚠️ 工具可能执行多次（Weather API 被调用 2 次）
- ✅ 这是已知的 M5 语义（documented in DurableExecutionEngine）

**Exactly-Once Checkpoint 转换**：
- ✅ CHECK B CAS 保证只有一个线程成功
- ✅ 失败者抛出 CheckpointTransitionConflictException
- ✅ 客户端可以捕获并决定是否重试

**未来幂等性（不在此任务）**：
- 需要 operationId / attemptId
- 需要工具执行去重
- 需要幂等性令牌

**当前行为保持不变**。
