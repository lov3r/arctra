✅ **87.5% 通用:**

✅ **EPHEMERAL 路径清晰:**
- 当前 execute() 无持久化

✅ **批准路径完整:**
- DurableResumeCoordinator 实现
- CHECK A/B 实现
- T5 集成

### 3.2 必须解决的问题

⚠️ **问题 #1: 非自描述的继续状态**

当前 SuspensionCheckpoint 无法回答:
> "这是 WAITING 还是 RUNNABLE 继续？"

**影响:** 恢复逻辑必须从使用上下文推断语义。

**解决:** 添加类型安全的继续倾向字段。

---

⚠️ **问题 #2: 无显式持久性选择机制**

当前通过构造函数 "all-or-nothing" 配置:
```java
new SpringAiToolCallingEngine(
    chatModel, tools, chatMemory, policy,
    checkpointStore,      // null = ephemeral
    bindingResolver,      // null = ephemeral
    runtimeBindingKey     // null = ephemeral
)
```

**影响:** 
- 引擎级别持久性，非执行级别
- 无法同一引擎支持 EPHEMERAL + DURABLE

**解决:** 添加执行级别的 DurabilityMode。

---

⚠️ **问题 #3: 无内部自动继续机制**

当前 `DurableResumeCoordinator.resume()` 假设:
- 外部触发
- 需要 ContinuationSignal

**影响:** 
- 无法表达内部自动继续
- DURABLE ALLOW 无法在物化后自动继续

**解决:** 
- 使 ContinuationSignal 可选
- 或添加内部继续原语

---

⚠️ **问题 #4: 工具结果持久性不明确**

需要确认:
- 正常成功的工具结果在哪里？
- ToolResponse 生命周期？
- Evidence vs. InvocationStateStore.recoveredResult 区别？
- 崩溃后如何重建模型继续输入？

**必须:** 源代码审计 ResumedExecutionHandler。

---

⚠️ **问题 #5: 初始 DURABLE 执行未实现**

当前 `SpringAiToolCallingEngine.execute()`:
- 无持久化逻辑
- 无 processId 创建
- 无 checkpoint 物化
- 无 operationId 分配前的持久化边界

**必须:** 实现 DURABLE 初始执行路径。

## 4. 架构决策需求

### 4.1 继续倾向表示 (CRITICAL)

**选项 A: 添加枚举字段到 SuspensionCheckpoint**

```java
public enum ContinuationDisposition {
    WAITING_FOR_SIGNAL,
    RUNNABLE
}

public record SuspensionCheckpoint(
    // ... 现有字段 ...
    ContinuationDisposition disposition  // 新字段
) {}
```

**优点:**
- 自描述
- 类型安全
- 明确语义

**缺点:**
- Schema 变更
- 需要迁移

---

**选项 B: 通过 pending batch 状态推断**

保持当前模型，通过业务逻辑推断。

**缺点:**
- 非自描述
- 脆弱的推断逻辑
- 违反 T6.4 要求

---

**推荐: 选项 A**

理由: T6.4 明确要求自描述。

---

### 4.2 持久性选择机制 (CRITICAL)

**选项 A: AgentExecutionContext 扩展**

```java
public record AgentExecutionContext(
    String sessionId,
    DurabilityMode durability
) {}

public enum DurabilityMode {
    EPHEMERAL,  // 默认
    DURABLE
}
```

**优点:**
- 执行级别控制
- 灵活
- 清晰语义

**缺点:**
- Public API 变更

---

**选项 B: 执行选项对象**

```java
public record ExecutionOptions(
    DurabilityMode durability
) {}

// 使用
runtime.execute(definition, request, context, options);
```

**缺点:**
- 更多参数
- 复杂性

---

**推荐: 选项 A**

理由: 
- AgentExecutionContext 已经是执行上下文
- 自然扩展点
- 向后兼容（默认 EPHEMERAL）

---

### 4.3 内部继续机制 (CRITICAL)

**选项 A: 使 ContinuationSignal 可选**

```java
AgentResult resumeInternal(
    String processId,
    long checkpointVersion,
    Optional<ContinuationSignal> signal,
    String currentExecutionEpoch
)
```

**优点:**
- 最小变更
- 复用现有逻辑

**缺点:**
- 混合语义

---

**选项 B: 独立的内部继续原语**

```java
AgentResult continueFromCheckpoint(
    SuspensionCheckpoint checkpoint,

```

**优点:**
- 清晰分离

---

**推荐: 选项 A**

理由: 收敛到统一管道，信号验证可条件化。
